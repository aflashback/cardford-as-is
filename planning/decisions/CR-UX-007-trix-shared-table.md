# CR-UX-007 — Trix uses the shared card-table experience

Recorded: 8 October 2026. Approval: the owner's explicit Trix UI review and subsequent card, doubling, score-history and landscape-device follow-ups. Applies to Basic Solo, Basic Partners, Complex Solo and Complex Partners; common artwork and seat placement also apply to Hearts and Spades. Rules, score arithmetic, legal subsets and persisted phases are unchanged. Read-only round-history contracts are additive.

The implementation extracts the already accepted Spades components into `web/src/table/`. Game adapters still supply their own legal candidates, competition, scores and public views; shared artwork does not make Spades trump/bids into Trix rules.

UX-42 records the owner's explicit 9 October gesture request and supersedes UX-22's no-autoplay preparation and ordinary pointer selection. A queued card is an explicit instruction to play when legal, not inferred from hovering or a single click. The shared `useHandGestures` hook owns that short-lived intent; it is never persisted across reloads. The existing adapter rechecks server legal candidates and decision identity before submission, and existing command/recovery fences remain authoritative. A picked face is a pointer-transparent copy of the canonical card, keeping the hit target fixed. The confirmed throw begins at the lifted or dropped rectangle and retains UX-38's final location. Reduced motion skips the pop/return/throw transitions. This adds no game rules, transport fields or backend actions. Acceptance is recorded in [the follow-up evidence](../../qa/implementation/trix/shared-card-followup.md).

For UX-41, projecting four integers from the existing server ledger avoids sending history eagerly or duplicating scoring rules in the browser. Dividing team bonuses between partners was rejected because those entries belong to the competitor rather than either individual. This is an owner-requested display correction, not a score-rule change.

Alternatives rejected: copying the Spades CSS again would keep design drift possible; inserting a server `trick-end` phase would change replay/contracts only to satisfy a visual pause; keeping the pause screen as a replacement unmounts table state; using a double-click toggle can immediately undo the first selection. The selected approach uses shared primitives and a presentation-only hold over recorded public tricks.

Compatibility: existing saved game/speed/access data and immutable original decisions remain valid. `TrixRoundIndex` and `TrixRoundHistory` are closed generated read DTOs at `/api/platform/rounds` and `/api/platform/rounds/{id}`. Live Trix transport carries empty ledger/withheld-bonus lists and adds `requestSeatTotals`, four integers in seat order, derived only from current-deal seat recipients. This field is optional in the schema for immutable historical observations; the native observation, engine, team-bonus arithmetic and saved decisions are unchanged. Historical totals use existing engine arithmetic. The watched frontend proxies only loopback API calls to the native Go authority and preserves the backend's exact-origin checks. No live provider or hosted rollout is introduced.
