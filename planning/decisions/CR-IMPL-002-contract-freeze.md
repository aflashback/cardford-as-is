# CR-IMPL-002 — Local V1 public contract freeze

Date: 2026-09-27. Status: implemented transport freeze; service and integrated acceptance remain separate.

## Authority and reason

The owner initiated the local three-mode B2C build, preserving the existing interface and current planning documents. CR-IMPL-001 and the local-build authorization supersede the old Spades-only/Jev-bot specification. This record freezes transport semantics before parallel consumers; it does not approve new rules, paid prices, hosted identity or model promotion. Requirements: IMPL-02, A03/A04, KNOW-01/02 and the W01 portion of strict boundary testing.

## Single source and generation

`web/shared/contracts.schema.json` is the active JSON Schema 2020-12 source. `web/scripts/generate-contracts.mjs` deterministically creates `contracts.ts`, `validation.ts` and `openapi.json`. OpenAPI references the canonical definitions, not copied DTO bodies. `--check` compares all generated bytes and exits nonzero for drift. Archived original schemas remain unchanged and inactive.

json-schema-to-typescript generates discriminated unions, required/optional fields and explicit nulls. Practical TypeScript arrays deliberately do not expand every bounded array into dozens of tuple alternatives. JavaScript numbers and strings likewise cannot express integer ranges or card regular expressions. The generated Ajv2020 validators retain every schema constraint, including array bounds, uniqueness, ranges, patterns, closed objects and conditional pass privacy. TypeScript is developer assistance, never proof that untrusted JSON is accepted. No independent DTO copy or second semantic validator exists.

Strict validation disables coercion, default injection and removal of unknown fields. Invalid input remains unchanged and is rejected. Response validation complements explicit allowlisted server projections; it cannot authorize a resource or prove that data was constructed from the right seat. The domain remains independently typed under server/game.

## Frozen public semantics

- Mode is Hearts, individual Spades or partnership Spades using the existing literals. Seats are 0 South/human, 1 West, 2 North, 3 East. Shared transport fields describe these closed installed games; they are not requirements imposed on a future generic domain module.
- `GameView.hand` is only the viewing player's hand. `handCounts`, scores, bids and tricks have four entries. `turn` and `currentWinner` are explicitly nullable; both must be null during sealed Hearts passing so the pre-exchange 2-clubs holder cannot leak. Received/outgoing contain only that player's permitted pass knowledge. There is no seed, all-hands field, raw event journal or server owner.
- Phase names preserve existing rendering. Fourth-card resolution and visible collection are separate domain transitions; the service must ensure score-once behavior. Transport does not implement scoring. Complete history tricks contain four public plays.
- Commands carry command ID, game ID, expected revision and control lease. The service resolves owner and actor and revalidates all relationships. `prepare` returns only an opaque prepared decision ID; it does not accept a trusted bot action. `advance` discriminates bot/collect-trick. Next hand has its own `/api/session/next-hand` route and the same envelope.
- Starting a session includes the expected current-game ID. The local service's GET session may create the default table using its own authorized default behavior; the returned contract is always SessionView. This local choice does not make production GET side effects a hosted design approval.
- Preferences preserve coach mode and the exact 1/1.2/1.4 speeds. Preferences have their own command ID and do not advance game revision. Account commands are separate account-level operations, with no caller-supplied grant.
- Advice includes recorded decision ID, requested level and truthful code/jev/forced/fallback source. The service must send only content authorized for the requested level and record issuance before response. These lifecycle obligations are not implied by DTO validity.
- Explicit control transfer uses the command envelope and x-tricks-tab header, with view-only represented by a non-authoritative lease string. Notes issuance uses POST with the envelope; NotesView contains only public memory and own pass facts. Original replay and Possible continuation have different literal labels. Frames contain safe GameView, selected action or null, decision ID and authored notes. Trials remain separate from live commands; all ownership/current-game boundaries are service responsibilities.
- Local account mode is explicit. The schema also supports a future managed adapter, without claiming one is integrated. Subscription status/coverage remain server supplied. Offers require null price and currency until owner-approved commercial configuration changes this schema. No real currency or price is invented.

## Alternatives and compatibility

Rejected hand-maintained TS/Zod/OpenAPI copies because they drift. Retained the existing flat UX view rather than forcing the old generic package layout into this build. Preserved private/public type separation. Rejected permissive schema stripping because sensitive accidental fields must fail visibly.

The old browser aggregate is intentionally not compatible with GameView: callers migrate from `hands[0]` to `hand` and use server legalActions/currentWinner. Existing pure engine types cannot be serialized directly. Future billing/family operations require their own reviewed contract extensions; this freeze is not a claim that all W01 hosted surfaces are delivered.
