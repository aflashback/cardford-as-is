# M02A portable public contracts and deterministic primitives

5 October 2026. Requirements: IMPL-02–04, MG-01–04/MG-09, SYS-01/SYS-02. Authorized by [CR-ARCH-003](../../decisions/CR-ARCH-003-backend-stack-and-system-readiness.md) and the owner's request to implement the next item. This is a compatibility foundation for the bounded Go slice; it does not activate a replacement application or claim all historical inputs are portable.

## Sources, generation and boundary

`web/shared/contracts.schema.json` and the public fragments registered in `web/scripts/generate-contracts.mjs` remain the sole editable public-schema sources. `scripts/m02a-contracts.mjs` reads that registration, rejects unregistered references, bundles those sources into an embedded Go artifact, and generates every named binding. The current registration is Hearts and Spades, with 99 combined definitions. The generator preserves the existing TypeScript schema, bindings and Ajv artifacts. The schema bundle and bindings are generated outputs, not another editable DTO tree. `--check` compares every generated byte, including source hashes and fixtures.

Go uses the root `cardford` module and `github.com/santhosh-tekuri/jsonschema/v6 v6.0.3`. M02A originally verified `go1.27.1`; [CR-ARCH-004](../../decisions/CR-ARCH-004-native-windows-performance.md) now pins **Go 1.26.8 on native Windows** after a same-source CPU-profile stability control. Public contracts, generated artifacts and dependency versions remain unchanged. The validator uses draft 2020-12, no coercion/defaults/property removal, and a loader which rejects every unregistered external resource. Bundled standard metaschemas are library-local. Regex compilation accepts only the reviewed source patterns; `\uNNNN` escapes translate to Go's `\x{NNNN}` spelling. A new pattern stops generation pending a compatibility review.

The public package is `cardford/server/internal/contracts`:

- `Validate(name string, raw []byte) error` validates one complete JSON value against the named active schema.
- `Decode(name string, raw []byte, out any) error` validates before decoding; use a generated named type as the destination. Generated types also validate when called directly through `json.Unmarshal` and `json.Marshal`.
- `Names()` returns a copy of the generated registry; `SchemaSHA256()` identifies the bundled artifact.
- `ParseJSON(raw)` checks data-only JSON syntax and representation limits. It deliberately does **not** validate a DTO or private-state shape; a caller must apply its registered semantic validator afterward.

Basic primitives, arrays and closed objects with representable fields are generated as typed Go bindings. Numeric wire fields use `float64`, reflecting JavaScript's binary64 domain rather than silently imposing an int64 range. Request envelopes including `CommandEnvelope`, `ActionsRequest` and `V2ActionsRequest` are typed. Complex unions, nullable mixed structures and their enclosing complex definitions are generated as opaque bindings with an unexported payload, validating `UnmarshalJSON`/`MarshalJSON`, and `RawJSON()` returning a copy. The generated manifest lists the exact binding kind for every definition. A zero opaque binding cannot encode; failed decoding cannot replace a previously validated value. Copying a binding or its returned bytes cannot mutate another binding. Opaque bindings preserve exact source bytes internally, including whitespace and numeric lexemes. Ordinary `json.Marshal` may compact or escape them as JSON normally does; canonicalization is a separate explicit operation.

Objects remain closed exactly where the source schema says so. Required fields, explicit null, absence, empty arrays, uniqueness, union tags, bounds and unknown nested fields are independently checked. Dates and IDs stay strings with the source constraints; many current date fields permit any nonempty text. Do not label those fields RFC3339-validated or convert timezone/precision silently. Required empty arrays must encode `[]`, not Go nil-slice `null`. Optional pointer fields preserve omission. Numeric `1.0` is an integer under the existing schema; wire spelling is not an integer-width promise.

## Deliberate strict-parser differences

The Go boundary limits one JSON document to 16 MiB and nesting depth to 128. HTTP admission can impose a smaller request cap. It rejects duplicate properties (including escaped aliases and nested duplicates), multiple roots/trailing tokens, invalid UTF-8, unpaired escaped UTF-16 surrogates, nonfinite/overflowing numbers and malformed JSON. It never accepts comments or trailing commas.

JavaScript `JSON.parse` retains only the last duplicate property and accepts unpaired surrogate strings. The checked fixture manifest explicitly identifies those cases where actual Ajv accepts a parsed value while the Go byte boundary rejects its representation. Go's standard decoder would silently replace malformed UTF-8/surrogates, so rejection is deliberate. Typed Go output also rejects invalid UTF-8 strings before encoding can replace them. A historical path containing such data requires the original compatible reader or an explicitly versioned migration; this slice must not pretend to preserve it.

Numbers are decoded to binary64 **before** schema validation, matching `JSON.parse` and Ajv rather than validating arbitrary-precision decimal lexemes. Consequently `9007199254740993` rounds to `9007199254740992` and can satisfy an unbounded public `integer` schema. The existing kernel's separate `Number.isSafeInteger` domain check remains necessary. `SafeInteger` uses the inclusive range −(2^53−1)…2^53−1 and rejects fractions/nonfinite values. Public-schema acceptance is not a claim that domain revisions/scores may exceed that range.

## Canonical bytes and existing digests

Three existing algorithms have distinct names and must remain distinct:

| API / original source | Exact supported behavior |
|---|---|
| `LegacyKernelCanonical` / `web/server/game/kernel/codec.ts:canonical` | Recursively sorts object keys with the legacy Node `localeCompare` behavior and directly emits members in that order. Arrays retain order. |
| `LegacyCommandCanonical` / `web/server/records/repository.ts` | Recursively applies the same collation, reconstructs objects, then follows `JSON.stringify` own-property enumeration: array-index keys 0…2^32−2 appear numerically before other keys. |
| `UTF16Canonical` / `web/server/evaluation/gate/runner.ts:canonicalJson` | Recursively sorts by UTF-16 code units as JavaScript default `.sort()` does. Arrays retain order. This is already a different algorithm and must not be substituted for a legacy digest. |

The legacy Go helpers support **ASCII alphanumeric object keys only**, matching the observed `en-US` ICU primary ordering and lowercase-before-uppercase tertiary tie order. Punctuation/Unicode keys fail with an explicit error. This covers the tested current command, Hearts/Spades packet and decision-envelope keys. It does not establish parity for arbitrary user-controlled dictionaries or every historical record. `localeCompare` has no portable locale-independent specification for all keys; retain the original reader for unsupported paths. The manifest pins the actual Node/ICU/locale used to derive the vectors. Numeric-key examples deliberately produce different kernel and command digests. Unicode scalar values in strings are supported; Unicode keys are supported only by the UTF-16 helper.

All helpers parse strict JSON first. They emit UTF-8, no whitespace, original array order, lowercase control escapes, and JSON string escaping without HTML or U+2028/U+2029 escaping. Binary64 values use shortest round-tripping decimal output with JavaScript's fixed/scientific thresholds: fixed for absolute values in [10^−6, 10^21), scientific outside, exponent sign retained with no leading zeros. Negative zero serializes as `0`. SHA-256 hashes exactly those resulting bytes. The tests compare bytes **and** digests with the actual TypeScript functions, including numeric boundaries/subnormals and production packet shapes; they do not silently rewrite any original identifiers.

Candidate IDs and order remain game/policy-owned. Preserve `C10`/`D10`/`H10`/`S10` (never replace with `T`); suit/rank card sorting is different from lexical ID sorting. Existing Spades observation-key hand sorting uses JavaScript UTF-16 `.sort()`. Tactical candidates retain their original ordered array, with the chosen tactical action first in the planning pack. Do not globally sort candidate IDs or change tie breaks. A strategy-policy port requires the original-policy corpus gate in addition to these primitive vectors.

## Arithmetic and randomness

`JSRound` reproduces `Math.round`, including ties toward positive infinity and negative zero for values from −0.5 through negative zero. It compares the fractional part instead of computing `floor(x + 0.5)`, which would incorrectly round values just below 0.5. Binary64 arithmetic remains binary64; no decimal arithmetic, epsilon tie rule or fused operation is introduced into a strategy port without explicit evidence/versioning.

`RandomVersion` stays `xoshiro128ss-splitmix-1.0.0`. `NewRandom(seed, stream uint32)` uses the exact TS splitmix initialization, uint32 overflow, shifts/rotations and eight warm-up draws. `Next` returns uint32; `Unit` divides it by 2^32. `Below` accepts 1…2^32, returns zero without consuming a draw for limit 1, and uses rejection sampling rather than modulo bias for the other limits. Nine actual-TS vectors cover zero/one/max seed and stream, sequential draws, difficult rejection limits and unit values. `HashText(text string) (uint32, error)` performs FNV-1a over UTF-16 **code units**, not UTF-8 bytes, and rejects invalid UTF-8 input instead of substituting replacement characters. Unpaired surrogate paths are intentionally unsupported at the JSON boundary.

This primitive does not replace the distinct legacy constraint sampler's private `randomSource`, whose source hash is recorded. That code uses a JavaScript numeric accumulating state and BigInt rejection/counting; it requires its own port and corpus gate. Normal dealing continues to require secure unbiased randomness and persisted actual deals/actions. Passing deterministic RNG tests does not establish secure dealing or seed-only historical replay.

## Verification and remaining scope

`qa/implementation/multi-game/m02a/contracts/` holds source hashes, binding inventory, actual-Ajv validation outcomes, deliberate boundary differences, canonical byte/digest vectors and deterministic arithmetic/RNG vectors. The shape witnesses for all installed validators establish schema behavior, not reachable game states or strategic quality. The Go tests round-trip every accepted witness through its generated binding and check failed decode immutability, opaque-copy isolation, malformed byte boundaries, external-reference rejection and the primitive vectors.

Run with Node 24 and the pinned Go toolchain:

```text
node scripts/m02a-contracts.mjs
node scripts/m02a-contracts.mjs --check
go test ./server/internal/contracts
```

Generation requires `gofmt` from the pinned Go installation. Current native Windows commands use the [project wrapper](windows-development.md), which sets `M02A_GOFMT_COMMAND` to the native 1.26.8 executable as a JSON argv array. The old WSL command remains only in historical M02A evidence:

```powershell
node scripts/windows-env.mjs node scripts/m02a-contracts.mjs --check
node scripts/windows-env.mjs go test ./server/internal/contracts
```

The evidence report records executed results. Complete private platform/history schemas, universal Unicode/legacy-collation parity, complete game/policy migration, preserved frontend journeys, hosted behavior, real providers and human evaluation remain outside this contract slice.
