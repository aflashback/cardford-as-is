# Private platform record contract

M03, 6 October 2026 (Toronto). Executable definitions live in [records types](../../../server/internal/records/types.go), [strict readers](../../../server/internal/records/document.go) and the [game codec](../../../server/internal/records/codec.go). These are server-private records, separate from the closed public game envelope. They are not HTTP responses or a browser export format.

## Version and identity

Platform records use `recordVersion: 1.0.0`; compact checkpoints use `events-separated-1.0.0`. Session metadata pins the exact game/variant, module, rules, private/public/observation/event schemas, competition, controllers and reasoning policy/budget/components. Missing or ambiguous pins never acquire a default. A trusted registration binds an execution policy to an exact module and input/output schema set. Merely supplying a policy name does not make a session playable.

The decoder rejects unknown/missing fields, duplicate keys, malformed Unicode, nulls outside their declared shapes and unsafe integer values. It validates the envelope before the game-owned payload. A supported reader can keep an unavailable policy's history read-only. A historical reader must supply the exact old opening/replay implementation as well as its decoder, so original advice can be verified at its source revision. It cannot start or advance live sessions. An unknown module without an installed trusted reader fails closed. `ReadLegacyState` preserves supported original V1 private state bytes; complete existing V1 platform documents still use the original TypeScript reader. There is no bulk conversion or policy repinning.

## Persistence and replay

M04E appends [010-platform-client.sql](../../../web/server/records/migrations/010-platform-client.sql). New profiles/preferences, local billing previews/family assignments, source-bound immutable help and bounded review jobs stay separate from original V1 records. A review job stores its original request/digest, source/live revisions, admission, seed, attempt and sampler version. Completed output is immutable; retry cannot substitute a new seed or policy. Family mutation/erasure takes its advisory lock before owner locks. Accepted help recovery checks the original grant even in the transactional duplicate branch. See [M04E evidence](../../../qa/implementation/multi-game/m04e/status.md).

| Record | Durable meaning |
|---|---|
| Current document | Validated bounded current state, revision and event count/byte/digest cursors; no duplicated complete event history |
| Replay anchor | Immutable original configuration, actual opening chance and initial checkpoint, bound to metadata |
| Events | Append-only ordered game events with source revisions and a chained digest |
| Commands | Original accepted operation bytes, actual later chance material, full intent digest and resulting checkpoint digest |
| Decision | Original actor/revision/window/purpose, input digest/version, policy/components, eligible selected candidate, original analysis/advice bytes and admission/attempt/receipt identity |
| Exposure | Append-only record of delivered content and time, referencing the original decision; it cannot rewrite that decision |

The command digest covers `recordVersion`, game identity, resulting revision and the canonical operation. The owner's command-ID namespace plus that digest identifies a retry. Reusing the ID with another game, revision or operation rejects.

A decision stores its input digest and revision, not another copy of its growing observation history. Historical validation reconstructs the original permitted packet from the private replay anchor and accepted operations. It never substitutes current information or a newer analysis. Original analysis, advice and accepted response bytes are retained without JSONB reformatting.

Game snapshots own their compact representation, event suffix, identity and access-unit identity. Current-hand knowledge stays in the snapshot. Frozen Spades policies still require all previous events in their original observations; those events are loaded once from the archive at the import boundary. Compact writes do not imply constant-size reads. The [growth evidence](../../../qa/implementation/multi-game/m03/status.md) distinguishes those costs.

## Publication and recovery

Load releases its database connection before game decoding, policy work or replay. A bound immutable snapshot prevents substitution of a different same-revision state. Publication rechecks the stored origin, owner, current game, revision, window, access/control generations, grant, unit and applicable prepared receipt. One short transaction commits the current snapshot, event suffix, command/checkpoint, decision reference, allowance charge and original accepted response together. Failure leaves none of those accepted writes behind.

Accepted-command reconciliation checks current ownership/read permission and the original intent digest before considering eligibility for new work. It can therefore return the original response after revision advancement, game replacement or loss of play coverage. It never grants another mutation or exposes another owner's result.

The Go and Node migration runners share the canonical SQL directory, `schema_migrations` checksum ledger and advisory lock. Migrations 001–008 remain byte-preserved; 007 added private platform history, and M04C added 008 for local identity, control, service receipts and account erasure. M04D adds [009-configured-access.sql](../../../web/server/records/migrations/009-configured-access.sql), recording configured identity mode and one immutable coaching unlock per actual game/unit. It backfills legacy allowance reservations using the first recorded command revision, with stable command ID as the fallback for imported charges without a command. Historical charges and their used quotas are retained unchanged, including any prior duplicate reservations. The original Go test entry remains restricted to isolated `_test` schemas. Explicit loopback local-service activation uses the separate fixed `cardford_go_local` schema. See [native run instructions](windows-development.md#m04c-local-go-api).

## Prepared work and access

Work is queued durably before dispatch, and one claimed attempt receives a finite fenced lease. States are `queued`, `running`, `completed`, `rejected` and `canceled`. Reclaim rejects an expired attempt's token. Publication checks the originally admitted actor, packet, policy, revision/window, unit and access/control generations. A completed work row points to the single immutable decision record; acceptance references those same bytes.

Unfinished terminal/expired work can be explicitly requeued under current valid bindings. An expired completed result remains readable and cannot be newly accepted. Its explicit retry creates a successor work identity while retaining the original result and receipt. Concurrent retries share one successor. Neither flow silently overwrites an issued result.

Access trials are separate from review alternatives. M03's trial ledger uses the server owner and stable trial key; M04D's configured commercial activation fixes that key across all offer IDs/versions and issues every selected exact target atomically. Devices, reloads, plan switches and replacement grant IDs cannot activate another trial. Grant/offer references and purchased terms remain immutable; revocation is explicit. Usage is keyed by owner, stable bucket and period. M04D's unit unlock pins the original grant, bucket, period, offer/version and tool coverage across new commands or grant edits. A hand crossing midnight retains its original charge period. Owner-lock serialization, finite-limit checks and receipt-first command reconciliation protect concurrent retries and the last available unit. Stable per-offer bucket/calendar checks survive process restart. UTC-day and lifetime buckets are implemented; other calendars fail configuration validation.

The game supplies the actual current unit. Natural expiry may finish only a recorded admitted unit when its terms permit; it cannot authorize the next hand. Freshly authorized control/device changes preserve those purchased finish rights while invalidating old prepared work. Current security revocation still denies operations. Play-only access permits the ordinary internal bot/human analysis; delivered coaching or a review alternative requires its own grant/tool and, in configured mode, a recorded unit unlock before coached work can queue, claim or publish. A separate coaching grant may serve an owned unit after play expires without permitting game advancement. Unlocking records that coaching grant's own admitted-unit validity; a play admission cannot silently broaden it. Saved delivered advice retains its original bytes across natural commercial expiry; source-grant or identity/read security revocation fences subsequent delivery and reads.

[Configured identity issuance](../../../server/internal/records/identity.go) installs only the selected automatic free templates, atomically with the server session. Empty launch configuration gives no grant. [Free-grant reconciliation](../../../server/internal/records/access_configured_free.go) adds new configured offers/targets with stable IDs while retaining original terms and explicit revocation. The persisted identity mode prevents a cookie from silently receiving M04C fixture grants after a configuration switch. [Authoritative context reads](../../../server/internal/records/access_context.go) supply consistent grants/admissions/usage/unlocks and original saved-delivery status; client boundary flags and plan names establish none of these records.

Saved review alternatives retain their original parent decision, eligible alternative, source packet digest and original result bytes. The future-exposure marker is conservative: a live revision beyond the parent indicates potential exposure, not proof that a human saw every later fact. M03 stores and validates the result; M04E supplies the bounded original one-trick continuation service. New M05 reasoning remains separately planned.

## Bounds and remaining integration

The record layer caps hot state at 256 KiB, archives at 16 MiB and events at 100,000, with safe-integer counters. Pool, connect, query and lock waits are finite. Work lifetime is at most ten minutes and an attempt lease at most thirty seconds. Oversized or stale work rejects before accepted publication; these are bounded local behaviors, not a production capacity claim.

[M04A](../../../qa/implementation/multi-game/m04/status.md) completes Go Hearts; [M04B](../../../qa/implementation/multi-game/m04b/status.md) adds original policy/coach parity and V2 sessions. M04C composes them with authenticated local public projections, durable exact preparation, HTTP recovery, atomic receipts and owner erasure; its scoped service acceptance passed ([evidence](../../../qa/implementation/multi-game/m04c/status.md)). [M04D acceptance](../../../qa/implementation/multi-game/m04d/status.md) passes the configured offer/record boundary described above within the MG-15/MG-16 backend scope. M04E implements complete platform/client integration and preserved three-mode journeys; its acceptance and remaining default-activation gate are recorded in [M04E status](../../../qa/implementation/multi-game/m04e/status.md). Installing a session adapter does not automatically change storage eligibility or pins. Complete original V1 history remains with its original reader. Hosting, live billing/providers and human evaluation remain separate work.
