## Findings corrected during integration

- The narrow M04C/D session endpoint could not drive the existing client. Add a separate closed platform envelope with game-owned presentation, the complete human legal-candidate packet, competition/controllers, preferences, access and committed assistance statistics.
- A configured account must not inherit fixture billing or an invented unlimited plan. The public account union now enforces distinct closed configured/fixture branches; initial conditional-schema TypeScript generation lost the account fields and was replaced with an equivalent discriminated union.
- New account methods need enforcement at publication, not just account display. Fixture profile/family/expiry checks now run under the same owner lock as creation, command commit, coaching publication and unlock. Family billing/erasure follows a consistent family-before-owner lock order; member changes invalidate admitted work.
- Generic command recovery originally bypassed source-grant revocation for newly delivered help/trials. Recovery now remains read-only, verifies original grant security and exact request digest, and retains natural-expiry readability of accepted output.
- Notes derive their source decision from the accepted revision. Recovery now uses that same derivation. Missing trial status returns 404 so the client can submit its first request; reconciliation retains explicit unknown/accepted semantics.
- Storage failure must not discard uncertain intent. The client refuses mutation before sending if durable storage cannot retain it. Raw control leases and family invitation credentials remain in owner-bound tab storage; persistent pending records retain only hashes and nonsecret exact input.
- Unlimited accounts require the same original unit reservation as limited accounts. The controller obtains it automatically on the first hint while preserving the existing one-click interaction.
- Original review indexes accepted human actions. Historical advice uses the original saved output. Continuations use an actor-observation-only feasible synthetic world, an explicit sampler version, original policy pins, a finite separate worker queue, immutable result and retry seed, and a source-unit/live-revision/control publication fence.
- Assistance aggregation was changed from scanning every possible revision and repeatedly scanning all help to sorting and merging actual source/delivery revisions.
- A measured completed Hearts hand contained 56 accepted decision records totaling 805,264 bytes. The session statistics reader originally loaded all of them before discarding bot actors. It now filters by the already-validated human accepted revision set before loading blobs (14 records per Spades hand, up to 17 for a Hearts passing hand because the sealed pass shares a revision). Accepted-command joins, size caps, strict decoding and source security stay intact. It deliberately does not require a work-row join: original accepted records may lack a worker record. This reduces selected history input; no wall-time or production-capacity claim is inferred. A regression covers unrelated oversized bot history and fail-closed malformed human history.
- Export now includes original human analyses whose source actually delivered platform advice, with original safe readers and grant checks. It does not rely solely on the old exposure table.
- Go owner IDs are 48 hexadecimal characters; the original V1 account schema requires UUIDs. A separate closed fixture account type now validates Go IDs without changing the original schema. This resolved the real account-projection HTTP 500 found during integration.
- The real family browser journey found the equivalent UUID constraint on invitation input. Additive `PlatformFamilyCommand` now accepts exactly 48 lowercase hexadecimal characters through HTTP, durable client recovery and reconciliation; original Node `FamilyCommand` stays UUID-based. Family responses already accept bounded native IDs. Real HTTP/PostgreSQL identities now cover create/invite/accept/leave, foreign-recipient denial, exact token receipt recovery, private member views and held seats. Cross-runtime fixtures reject uppercase, short, UUID and trailing-newline variants.
- Definite terminal continuation failures clear both persistent and React pending state; uncertain transport failures retain exact intent. Delivered level-three advice has a read-only path after natural expiry. Concurrent duplicate help publication rechecks the original delivery grant under the same owner/grant locks before returning an existing receipt. Independent review identified all three edge cases.
- Rapid hint escalation exposed a real browser race: the UI displayed the next stage before its response arrived, allowing a second request while advice/exposure was still pending. Stages now reflect confirmed output; synchronous request serialization blocks repeated clicks through exposure recording. Delayed-response and repeated-click tests exercise the behavior.

## Backend resource readiness finding

[ReadDecision](../../../../server/internal/records/store_history.go) loads the owned decision and then replays the complete archive to validate its source historical decision/checkpoint, even when the caller has already loaded current state. That extra replay is not safely replaced by current `Load` validation: the historical corruption checks protect a different binding. [Spades state cloning](../../../../server/internal/games/spades/snapshot.go) also copies cumulative `Events` during transitions; nested historical reads and replay can multiply growing history costs. These inspected paths are concrete profiling targets, not measured root causes of the censored Solo match or prior PostgreSQL errors. No replay/checkpoint safeguard or runtime deadline is bypassed by the scoped acceptance adjustment. Complete normal-match/resource evidence remains a prerequisite to default activation.
